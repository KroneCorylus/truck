# R9: fine revolution meshes

The original application fixture is `R9-revolve-shaft.json`, a compressed modeling
solid with radius 5 mm, height 10 mm and twelve faces. Its flat quarter caps are
revolved radial curves, not plane surfaces. The fixture is unchanged from the
report (SHA-256 `76e7f843225553d216bdf7896e42d54e6243499235ab4ce65ac18a10c605597f`).

## Correction

Interior refinement now measures the surface sample's distance from the two
adjacent triangle planes. Comparing a parameter midpoint with a spatial chord
midpoint incorrectly measured tangential parameter distortion on flat polar caps.
The existing one-direction refinement gate and shared boundary constraints remain.
The stepped-extrusion diagonal regression and R7/R8 reference volumes still pass.

The previous refinement also created spatially inverted cap triangles. A diagnostic
build of `3412863f` with only the new welding algorithm counted 38 such triangles
before normal alignment. Individually reversing these triangles to match surface
normals breaks consistent edge orientation: the welded mesh remains `Regular`,
not `Closed`. This reproduces the topology failure independently of the memory
failure. Avoiding unnecessary polar-cap refinement restores the closed mesh.

Welding now traverses connected components directly from the existing spatial
buckets, removing discovered candidates instead of materializing every matching
pair. Every discovered attribute is searched in turn, so tolerance chains still
merge. The strict squared-distance comparison and selection of an attribute nearest
the component mean remain. Storage is linear in the attribute count; groups of
equal attributes no longer require quadratic pair comparisons either.

Tests retain normal attributes, check closure/orientation and input nonmutation,
and require volume error below 0.3 mm³ at 0.001 mm tolerance. The supplied per-face
and no-normal diagnostics remain, with tighter mesh-size bounds. Welding tests cover
100,000 equal positions, UVs and normals, strict tolerance, transitive chains and
randomized comparison against exhaustive pairwise connected components.

thread; the test processes ran under a 2 GiB address-space limit and 60 s timeout.
These are diagnostic timings, not portable performance assertions.

An isolated copy of the application's current source used local kernel dependencies;
the application's working tree and revision pin were not edited. All four core
tests matching `revolve` passed in 50.59 s, including full/quarter/reversed shafts
and groove edits plus JSON save/load. A temporary control test built the same
full-turn shaft in an isolated headless Sway window and called `body.mass`:
23 ms, volume 785.196315181 mm³, centroid approximately (0, 0, 5), and unchanged
document data, at the application's 0.001 mm measurement tolerance. Display
tolerance remained 0.05 mm.

The complete `truck-meshalgo` and `truck-shapeops` suites passed 226 tests across
25 suites (two existing ignored tests). The application's four measurement tests
and window-based revolve menu/undo/save/load test also passed. Meshalgo library
and test Clippy, nightly formatting, and `git diff --check` passed.

## Reproduce

```sh
CARGO_PROFILE_TEST_OPT_LEVEL=1 cargo test -p truck-meshalgo --test R9-revolve-fine-tessellation
CARGO_PROFILE_TEST_OPT_LEVEL=1 cargo test -p truck-meshalgo --lib filters::optimizing::tests
CARGO_PROFILE_TEST_OPT_LEVEL=1 cargo test -p truck-meshalgo --test tessellation
CARGO_PROFILE_TEST_OPT_LEVEL=1 cargo test -p truck-shapeops --test R7-R8-extrude-remove
```

For allocation-limit validation, build with `--no-run --message-format=json`, take
the `executable` from the compiler artifact, then run that binary with
`RAYON_NUM_THREADS=1`, `--test-threads=1`, `RLIMIT_AS=2*1024**3`, `RLIMIT_CORE=0`
and a 60-second process timeout. Apply these limits to the test, not the compiler.
